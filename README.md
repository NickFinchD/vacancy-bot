# vacancy-bot

Телеграм-бот присылает новые удалённые вакансии с hh.ru в первые минуты
после публикации.

Смысл в скорости: рекрутер разбирает отклики сверху вниз и до сотого обычно
не доходит. Попасть в первые десять откликов важнее, чем написать красивое
сопроводительное — бот существует ровно ради этого.

## Команды

| Команда | Что делает |
|---|---|
| `/add python` | Подписаться на поисковый запрос |
| `/list` | Показать мои подписки |
| `/del python` | Отписаться |

## Запуск

```bash
pip install -r requirements.txt

export BOT_TOKEN=токен_от_BotFather
export HH_USER_AGENT="vacancy-bot/1.0 (github.com/NickFinchD/vacancy-bot)"
python -m bot.main
```

## Стек

Python 3.11+ · aiogram 3 · httpx · sqlite3 · pytest

## Как устроено

```
bot/
├── storage.py   подписки и история отправок, голый sqlite3
├── hh.py        клиент к API hh.ru — только поиск свежих вакансий
├── matcher.py   отбор новых и форматирование сообщений — чистые функции
└── main.py      команды бота и фоновый опрос
```

Опрос идёт раз в 15 минут по всем подпискам. Для каждой берутся вакансии
за сутки, отсортированные по времени публикации, и отправляются только те,
что этому чату ещё не уходили.

## Принятые решения

**История отправок в базе, а не в памяти.**
Бот перезапускается — при хранении в памяти подписчик получил бы всё заново.
Первичный ключ `(chat_id, vacancy_id)` делает повторную отправку невозможной
на уровне схемы, а не логики.

**Не больше 5 сообщений за проход.**
У Telegram есть лимит частоты, а подписчик, которому прилетело 40 сообщений
подряд, отписывается. Остальное уйдёт следующим проходом.

**Разметка HTML, а не Markdown.**
Markdown в Telegram ломается на спецсимволах в названиях компаний
(«Рога & Копыта», «Разработчик C++»). HTML экранируется предсказуемо.

**Запрос нормализуется при сохранении.**
`Python`, `python` и ` python ` — одна подписка. Иначе пользователь незаметно
для себя подписывается трижды и получает дубли.

**Логика отделена от транспорта.**
`matcher.py` — чистые функции без сети и без базы. Поэтому тесты проходят
за миллисекунды, без токена и без поднятия бота.

**Ошибка одной подписки не роняет цикл.**
Если hh не ответил на один запрос или пользователь заблокировал бота —
логируем и идём дальше, остальные подписчики своё получают.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Покрыты: идемпотентность подписок, нормализация запроса, изоляция данных
между чатами, защита от повторной отправки, лимит на проход,
форматирование зарплат и экранирование HTML.
